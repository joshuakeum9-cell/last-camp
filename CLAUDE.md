# LAST CAMP — working rules

Read `ARCHITECTURE.md` in full before changing anything. It is the approved design and the
source of truth for file layout, data shapes and every number.

## Hard rules

1. **Never add a system, scene, resource or currency that is not in ARCHITECTURE.md.** If
   something seems missing, ask first.
2. **Systems never touch Phaser display objects.** Files under `src/systems/` and `src/core/`
   are plain TypeScript that read and write `GameState` and talk over `EventBus`. Scenes and
   entities do the rendering. Exceptions that genuinely need a scene (Weather, Lighting, Juice,
   AudioManager) take the scene as a constructor argument and own only their own objects.
3. **Keep every file under ~350 lines.** Split before that.
4. **No external binary assets.** All art is generated by `src/art/PixelFactory.ts` from pixel
   maps; all audio is synthesised by `AudioManager`. No PNG, no MP3, no font files.
5. **All tunable numbers live in `src/data/balance.ts`** or the other `src/data/*.ts` files.
   Logic files must not contain magic numbers that a designer would want to change.
6. **No em dashes in player-facing text.** Use a full stop or a comma.
7. Priority when anything conflicts: movement feel > combat feel > gathering feel > return feel
   > visible upgrades > curiosity > time pressure > story > retention extras > store prototype.

## Build phases

Phases and their pass gates are in ARCHITECTURE.md section 13. Finish and verify one phase
before starting the next. After each phase: run the dev server, open the in-app browser
preview, check the console is clean, take a screenshot.

## Commands

```
npm install
npm run dev        # Vite on http://localhost:5173
npm run typecheck  # tsc --noEmit
npm run build
```
